### 🥒 Escenarios Gherkin (v20)

### 🎨 @ui @ux
**Escenario: Confusión por iconografía genérica en botón contextual**
- **Dado** que estoy en la pantalla de "Gestión de Aciertos"
- **Cuando** visualizo una jugada ganadora
- **Entonces** el sistema muestra un botón "+" para realizar acciones
- **Y** al presionarlo se despliegan las opciones "Imprimir" y "Ver detalles"
- **Pero** el icono "+" resulta poco intuitivo para estas funciones específicas

### 🔄 @logica
**Escenario: Ausencia de opción Repetir en tickets anulados**
- **Dado** que he emitido un ticket recientemente
- **Y** procedo a anular dicho ticket correctamente
- **Cuando** vuelvo a escanear o consultar el ticket anulado
- **Entonces** el sistema solo muestra información del estado "Anulado"
- **Pero** no aparece el botón "Repetir" que sí está presente en el Historial

### 💰 @validacion
**Escenario: Alerta por importe no considera el acumulado del carrito**
- **Dado** que el umbral de alerta está configurado en $1000
- **Y** tengo un carrito con 5 jugadas de $300 cada una (Total: $1500)
- **Cuando** procedo a realizar la emisión del carrito
- **Entonces** el sistema no dispara ninguna alerta por importe
- **Pero** el total acumulado supera el umbral definido individualmente

### 🔒 @seguridad @bug
**Escenario: Visibilidad del PIN en texto plano en Alerta por Importe**
- **Dado** que la opción "Requerir PIN" está activa en Alerta por importe
- **Cuando** el sistema solicita el PIN para confirmar la configuración
- **Entonces** el campo de entrada muestra los números en texto claro
- **Pero** por privacidad debería mostrar caracteres enmascarados (***)

### 🔄 @consistencia @bug
**Escenario: Desincronización de PIN entre Preferencias y Alerta**
- **Dado** que cambio el PIN de seguridad desde el menú de "Preferencias"
- **Cuando** se dispara una "Alerta por Importe" que requiere PIN
- **Entonces** el sistema sigue solicitando el PIN viejo o mantiene uno propio
- **Pero** debería existir una única fuente de verdad para el PIN en toda la app

### ⌨️ @ux @navegacion
**Escenario: Falta de botón de confirmación en cambio de PIN**
- **Dado** que intento cambiar un PIN ya establecido
- **Cuando** ingreso el PIN actual para validar
- **Entonces** la interfaz solo muestra el input y el botón "Cancelar"
- **Pero** falta el botón "Confirmar" o "Siguiente", obligando a usar el teclado externo

### 🎰 @bug @loteria
**Escenario: Falla en opción Entero de Lotería y fracciones fantasma**
- **Dado** que se han vendido 9 de 10 fracciones de un billete de Lotería
- **Cuando** selecciono la opción para vender el "Entero" (lo que resta)
- **Entonces** el sistema falla al intentar autorizar la transacción
- **Y** el dropdown de fracciones muestra opciones del 2 al 9 que ya no existen

### 🚧 @bloqueo @testing
**Escenario: Imposibilidad de testear Reservas de Lotería**
- **Dado** que accedo al módulo de Reservas de Lotería en ambiente de Testing
- **Cuando** intento ejecutar los escenarios de prueba definidos
- **Entonces** las funciones de reserva no responden o fallan por falta de datos
- **Pero** se requiere validación funcional para cerrar el bloque de Lotería

### 🔐 @investigacion @auth
**Escenario: Observación de Refresh token rechazado**
- **Dado** que el POS intenta renovar la sesión con "POST sesiones/refresh"
- **Cuando** bsecurity responde HTTP 403 "Forbidden"
- **Entonces** el POS realiza un fallback automático a "POST login" (OK)
- **Pero** se requiere analizar por qué el refresh token no es válido para bsecurity

### 🌙 @infraestructura @log
**Escenario: Caída nocturna de bsecurity registrada en logs**
- **Dado** que se analizan los logs del 17/03 entre las 00:00 y las 11:22
- **Cuando** el sistema realiza el CheckConnectionTask
- **Entonces** se registran fallos continuos por timeout de 30 segundos
- **Y** el servicio se recupera automáticamente a las 11:22:18 (Environment: testing)

### ⚡ @bug @cierres
**Escenario: Sorteos no se actualizan tras inactividad (Doze Mode)**
- **Dado** que la terminal queda inactiva durante un periodo prolongado (noche)
- **Cuando** llega la hora de cierre y apertura de nuevos sorteos
- **Entonces** la terminal no refresca la lista de sorteos automáticamente
- **Y** muestra información desactualizada al operador
- **Pero** el POS debería forzar el refresco de los sorteos al despertar

### 📶 @validacion @offline
**Escenario: Detección inmediata de falta de conexión**
- **Dado** que el POS está operando normalmente con conectividad
- **Cuando** se desactiva el WiFi y los datos móviles simultáneamente
- **Entonces** el sistema muestra inmediatamente un indicador rojo "Sin conexión"
- **Y** no permite avanzar con operaciones que requieran backend

### 🕐 @validacion @cierres
**Escenario: Solo sorteo Nocturno disponible después de las 14 horas**
- **Dado** que la hora actual del sistema es posterior a las 14:00
- **Cuando** el operador accede a la pantalla de apuestas de Quiniela
- **Entonces** solo el sorteo "Nocturno" está disponible para apostar
- **Y** el sorteo "Vespertino" ya no aparece en la lista

### ❌ @validacion @anulacion
**Escenario: Anulación exitosa de ticket diferido de 5 de Oro**
- **Dado** que se emitió un ticket de 5 de Oro para sorteos futuros
- **Y** el sorteo aún no ha cerrado
- **Cuando** el operador solicita la anulación del ticket
- **Entonces** el sistema anula el ticket correctamente
- **Y** actualiza el estado en el historial de transacciones
